## 배포 방침

사용자 결정: **알림 작업과 다른 세션에서 진행 중인 개선 작업을 모두 마친 뒤 한 번에 배포한다.**

- 알림 작업만 단독으로 배포하지 않는다. 현재 버전은 `0.0.11`이며 다음 배포 버전은 아직 정하지 않았다.
- 다른 세션의 개선 작업 범위와 완료 여부는 이 기록에서 확정하지 않는다. 아래 내용은 알림 작업의 인계 기록이다.
- 현재 로컬 `YourSQL.app`, `dist/YourSQL-darwin-arm64/`, `dist/YourSQL-win32-x64/`, `dist/YourSQL-Windows-x64.zip`은 알림 작업 시점의 검증용 산출물이다. 이후 개선 내용이 포함된 최종 배포본으로 간주하지 않는다.
- 통합 작업 완료 후 최종 소스로 Mac·Windows를 함께 다시 빌드하고, Windows ZIP도 새 폴더 전체로 다시 만든다.
- 이 세션에서 커밋·푸시·공개 릴리스는 하지 않았다. 변경 내용은 작업 디렉토리에 남아 있다.

## 업데이트 내용 초안 — 오후 8시 학습 알림

- 설정의 하루 학습량 아래에 **학습 알림**을 추가했다. **오후 8시 학습 알림** 스위치, **테스트 알림**, 등록 실패 시 **다시 시도**를 제공하며 기본값은 꺼짐이다.
- 현지 시각 오후 8시에 **오늘 완료한 사이클 수가 오늘 목표보다 적을 때** 하루 한 번 알림을 요청한다. 한 사이클은 기존 빈칸 6문제와 SQL 작성 2문제이며, 전체 풀이 수를 8로 나누어 판정하지 않는다.
- 목표 변경은 오늘부터 반영한다. 목표 달성 후 추가 학습 중이거나 전체 과정이 끝나 더 배정할 문제가 없으면 알림을 생략한다.
- 앱 종료 상태에서는 Mac LaunchAgent / Windows Task Scheduler가 알림 검사 전용 모드를 잠시 실행한다. 검사만 할 때는 창과 MySQL 엔진을 만들지 않는다.
- 절전·로그인 등으로 놓친 검사는 당일 20:00 이상 22:00 미만에 다시 평가한다. 컴퓨터를 강제로 깨우거나 전날 알림을 이월하지 않는다.
- 알림 설정·시도 날짜·오류는 `reminders.json`에 별도로 보관한다. 학습 파일은 읽기만 하며 손상·읽기 오류가 있으면 알림을 생략한다.
- 알림 검사 자체는 현재 화면과 SQL 초안을 바꾸지 않는다. 클릭 시 기존 초안 저장 경로를 통해 오늘의 학습 화면으로 이동을 요청한다.
- 구버전 3+1 배정도 화면과 알림이 동일하게 오늘의 6+2 기준으로 판정하도록 공통 처리했다. 과거 완료 사이클과 원본 기록은 보존한다.
- Windows 제거 시 예약 작업, 알림 바로가기, 64비트 알림 등록을 정리하도록 구현했다. Windows에서 실제 제거 동작은 아직 미검증이다.

사용 방법·저장 정책·제거 방법은 [학습 알림 문서](daily-reminders.md)를 참고한다.

## 안정성 개선 통합 작업 — 2026-09-22

위 ‘알림 작업 시점’ 기록 이후, 다른 터미널 작업의 완료·정지를 확인하고 현재 알림 소스를 기준으로 이어서 수정했다. 브랜치는 `reliability-and-reminders-20260922`이며, 기존 알림 변경은 `27780a9`에 별도 보존했다. 아래 작업의 커밋은 기존 알림 작업과 구분된다. 푸시·공개 릴리스는 하지 않는다.

### 추가한 변경

- **필수 쿼리 완료 판정:** 40개 단원의 빈칸 6개와 필수 쿼리 2개를 모두 확인한다. 구형 과거 사이클의 확인 가능한 정답을 함께 계산한다. 쿼리가 남으면 다음 날 같은 단원을 새 6+2로 배정하고 오늘 실적은 0부터 시작한다. 잘못된 오늘 완료 플래그를 보정하며 과거 달력과 SQL 초안은 보존한다.
- **검증·백업·복구:** 검증된 직전 정상 파일만 `.bak`으로 보관한다. 손상 원본을 고유한 이름으로 보존한 뒤 정상 백업으로 복원한다. 복구 불가 시 창과 안내를 열고 학습·자동 저장을 제한한다. 기록 폴더 열기·재시도·복원 시점 안내를 제공한다. 손상 오답 한 파일은 정상 오답을 막지 않는다.
- **알림 설정 복구:** 오래된 백업이 알림을 다시 켜지 않도록 꺼짐으로 복원하고 당일 자동 알림을 보류한다. 사용자가 다시 켜도 복구 당일 중복 방지 표식은 유지한다. 알림 전용 실행은 복구 없이 읽기만 한다.
- **종료:** SQL 실행이나 초안 저장 실패로 종료를 보류하면 알림 감시를 유지한다. 종료 확정 후 감시·엔진을 한 번만 정리한다. 중복 monitor/dispose와 비동기 감시 시작 도중 종료도 처리한다.
- **Windows 제거:** 설치 경로와 소유 사용자가 일치하는 대상만 종료·정리한다. 정상 종료 우선, 일반 제거의 재시도·강제 종료·취소, 무인 제거 `/FORCE` 명시, 실제 잠금이 유지되는 동안만 재실행 차단, 예약 삭제 확인과 실패 복원, 제거 재시도 정보 보존을 추가했다. 설치 시 기존 강제 종료 정책은 유지한다.
- **Windows ZIP:** 매번 새 전체 폴더를 압축하고 숨김 파일을 포함한 목록·모든 파일 SHA-256을 추출본과 비교한다. 이전 ZIP 삭제 정책을 제거했다. `package`가 Mac·Windows 앱과 새 Windows ZIP을 함께 만든다.

### 이 시점의 검증

- `npm test`: **95개 통과**. 완료 판정·저장소 오류 주입·알림 복구·종료·제거 가드·ZIP 검사 포함.
- `npm run test:ui`: 기존 6+2 학습·설정·MySQL 채점·복습·재시작 통과.
- `node tests/recovery-ui.cjs`: 손상된 학습·초안 파일에서 창 유지, 변경 차단, 재시도와 백업 복원, 초안 보존 통과. 복구 전후 화면 확인.
- `npm run test:daily-reminder`: SQL 실행/초안 저장 실패 후 종료 보류, resume 감시 유지, 화면 이동과 초안 보존 통과.
- UI 변경 정적 검사: 추가 지적 없음.
- Windows 전용 검사에는 정상·알림·무응답 제거, 명시적 강제, 다른 설치본 보존, 실제 파일 공유 잠금, 중단된 제거 복구, 예약 삭제 권한 거부, 삭제 중 파일 잠금과 재시도, 사용자 기록 해시 비교를 추가했다. **이 Mac에서는 실행하지 않았다.**

### 최종 코드 리뷰 보완

별도 검토자의 전체 변경 리뷰에서 나온 세 항목을 수정했다.

- 알림 백업 복원 후 별도 저장이 실패하면 과거 `enabled: true`가 남을 수 있던 경로를 제거했다. 꺼짐·당일 보류 표식을 복원 값에 먼저 반영하고 한 번에 원본을 교체한다. 디스크 부족 후 알림 전용 재시작 검사가 수정 전 실패, 수정 후 통과했다.
- 현재 날짜가 누락·공백·null이거나 날짜 키와 다르면 정상 기록으로 처리하지 않는다. 정상 백업 복원과 백업 바이트 보존 검사가 수정 전 실패, 수정 후 통과했다.
- Windows 제거의 마지막 레지스트리 삭제 실패도 제거 프로그램·재시도 등록을 복원하는 경로로 연결했다. 해당 ACL 거부 검사를 Windows 검사에 추가했다. 실행 결과는 미검증이다.

최종 핵심 검사 **95/95**, 저장·알림 복구 집중 검사 **33/33** 통과. 리뷰에서 남긴 경미한 지적은 없다.
